Модель оценивает вероятность того, что клиент телеком‑компании уйдёт, и помогает отделу удержания решить, кому звонить в первую очередь.

## 🎯 Задача

Бинарная классификация: предсказать `Churn` (ушёл / остался) по данным о клиенте — тарифу, подключённым услугам, способу оплаты и сроку обслуживания.

## 📊 Данные

Открытый датасет [Telco Customer Churn](https://www.kaggle.com/datasets/blastchar/telco-customer-churn): 7 043 клиента, 20 признаков, **26.5%** ушедших.

## 📈 Подход

### 1. Подготовка признаков — `src/features.py`
Одна функция `add_features` используется и при обучении, и в приложении, поэтому данные всегда обрабатываются одинаково.

- `TotalCharges` переводится в число; 11 пропусков — клиенты с `tenure = 0`, они заполняются нулём.
- Новые признаки:
  - `tenure_group` — срок обслуживания по группам (0–6, 6–12, 12–24, 24–48, 48+ мес.);
  - `avg_charge` — средний платёж за всё время (`TotalCharges / tenure`);
  - `charge_diff` — разница между текущим и средним платежом (сигнал об изменении тарифа);
  - `count_services` — число подключённых услуг.

### 2. Pipeline
Очистка, кодирование и модель объединены в один sklearn `Pipeline`. Это исключает утечку данных при кросс‑валидации (масштабирование и кодирование обучаются только на обучающих фолдах) и позволяет приложению передавать модели сырые данные.

### 3. Валидация
- 20% данных отложены в тест и используются **один раз** — для финальной оценки.
- Гиперпараметры подбираются `GridSearchCV` на 5 фолдах по **PR‑AUC** — при 26% положительного класса она больше всего несет информацию
- Порог классификации выбирается по **максимуму F1** на out‑of‑fold предсказаниях, а не на тесте.

### 4. Сравнение моделей — `experiments.ipynb`
Четыре модели с исходными параметрами оцениваются на одних и тех же фолдах с одинаковыми признаками (5 фолдов):

| Модель | PR‑AUC | ROC‑AUC | F1 |
|---|---|---|---|
| **CatBoost** | **0.659** | 0.845 | **0.640** |
| Logistic Regression | 0.658 | **0.847** | 0.638 |
| Random Forest | 0.621 | 0.827 | 0.616 |
| Neural Network (PyTorch) | 0.527 | 0.783 | 0.572 |

- CatBoost и логистическая регрессия практически равны и заметно лучше остальных.
- Нейросеть сильно переобучается: val loss минимален на 2‑й эпохе, а обучение идёт 300 эпох.
- Random Forest без ограничений на глубину деревьев запоминает обучающие данные.

Для дальнейшей работы выбран CatBoost: сам работает с категориальными признаками и не уступает остальным.

### 5. Финальная модель — `notebook.ipynb`
Параметры CatBoost (`depth`, `learning_rate`) подобраны `GridSearchCV`. Лучшим оказался `depth=1` — модель складывает эффекты отдельных признаков без их взаимодействий, поэтому и сравнима с логистической регрессией. После подбора PR‑AUC на кросс‑валидации вырос до **0.665**.

## 🏆 Результаты на тестовой выборке

Финальная модель — CatBoost, порог **0.342**. Тестовая выборка (1 409 клиентов) не участвовала ни в обучении, ни в подборе параметров и порога.

| Метрика | Значение |
|---|---|
| PR‑AUC | **0.670** |
| ROC‑AUC | **0.846** |
| F1 | **0.636** |
| Recall | 0.733 |
| Precision | 0.561 |

**Что это значит:** модель находит **~73% клиентов, которые действительно уйдут**, и **больше половины** клиентов из её списка риска действительно уходят — вдвое больше, чем при случайном выборе (26.5%).

Порог можно сдвигать под бюджет удержания: ниже порог — больше пойманных уходящих, но больше лишних контактов.

## 💡 Факторы оттока и рекомендации

Самые важные признаки модели: `Contract`, `tenure`, `TechSupport`, `InternetService`, `OnlineSecurity`. Доля ушедших по группам:

| Фактор | Группа риска | Надёжная группа |
|---|---|---|
| Контракт | помесячный — **42.7%** | двухлетний — 2.8% |
| Срок обслуживания | 0–6 мес. — **52.9%** | 48+ мес. — 9.5% |
| Интернет | Fiber optic — **41.9%** | DSL — 19.0% |
| Техподдержка | не подключена — **41.6%** | подключена — 15.2% |
| Способ оплаты | Electronic check — **45.3%** | автоплатёж картой — 15.2% |

Рекомендации:
- **Переводить клиентов на долгосрочные контракты** — например, скидкой при переходе с помесячного тарифа.
- **Программа адаптации для новых клиентов**: первые 6 месяцев — самый рискованный период.
- **Предлагать пробный период TechSupport и OnlineSecurity** — с ними клиенты уходят почти в 3 раза реже.
- **Стимулировать автоплатежи** вместо Electronic check.


## 🚀 Локальный запуск

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/tryhardsummer/telco-churn-prediction.git
   cd telco-churn-prediction
   ```
2. Создайте окружение (Python 3.11) и установите зависимости:
   ```bash
   python3.11 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```
3. Скачайте [датасет с Kaggle](https://www.kaggle.com/datasets/blastchar/telco-customer-churn) и положите его в корень проекта как `Dataset.csv`.
4. Запустите приложение:
   ```bash
   streamlit run app/streamlit_app.py
   ```
5. Ноутбуки запускаются из папки `notebook/` в порядке: `Telco_Churn_Project.ipynb` → `experiments.ipynb` → `notebook.ipynb`. Последний пересохраняет `models/churn_pipeline.pkl`.
